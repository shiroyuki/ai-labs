# Design Principles (Dieter Rams)

Apply these 10 principles to software engineering tasks (UI, UX, and System Design).

## 1. Good design is innovative.
Technical innovation should solve problems in new ways, not just replicate existing patterns.

## 2. Good design makes a product useful.
Prioritize functionality. Can the user achieve their goal with the fewest clicks?

## 3. Good design is aesthetic.
Clean UI, consistent spacing, and clear visual hierarchy.

## 4. Good design makes a product understandable.
The interface should be intuitive. Users should know what to do without instructions.

## 5. Good design is unobtrusive.
The UI should disappear into the background. Don't over-decorate.

## 6. Good design is honest.
Don't deceive users. A "Download" button shouldn't perform a "Delete" action.

## 7. Good design is long-lasting.
Avoid "trendy" UI elements that will feel dated in 6 months. Stick to standards.

## 8. Good design is thorough down to the last detail.
Handle edge cases, empty states, and error messages with the same care as the primary flow.

## 9. Good design is as little design as possible.
**Less, but better.** Remove unnecessary features and complexity.

## 10. Good design is environmentally friendly.
In software, this means efficient code, low resource consumption, and sustainable development practices.

## Application Guide
- **When reviewing code:** Check if the implementation follows these principles (e.g., "Is there any unnecessary complexity here?").
- **When designing APIs:** Focus on "Understandable" and "Useful".
- **When building UI:** Focus on "Aesthetic", "Unobtrusive", and "Least design possible".
